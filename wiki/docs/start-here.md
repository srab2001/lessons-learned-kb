# Start Here — KB Workflow

**This page maps the KB in the order you'll use it.**

---

## The 4-step KB workflow

```
1. BEST PRACTICES  →  2. RECOMMENDATIONS  →  3. RETROSPECTIVES  →  4. REUSE
```

---

### Step 1 — Best Practices: Find the proven approach

**Start here.** Best practices tell you *what has worked* — canonical, evidence-backed practices the org has proven out.

**Action:** Read the [Best Practices index](best-practices/index.md). Which practice maps to the work you're about to start?

---

### Step 2 — Recommendations: Pull the evidence

Go to the [Explore Recommendations](explore.md) page. Filter by:

- **Capability** — matches the workstream you're planning
- **Lesson type** — process / technical / people-org / client-relationship / tooling
- **Confidence: high** — only rely on `high` confidence recommendations without caveats; `medium` with attribution

See the [Recommendations index](recommendations/index.md) for the full capability list.

---

### Step 3 — Retrospectives: Anchor to a project

Recommendations are only as credible as the projects behind them. Map each recommendation to a retrospective record for context.

See the [Retrospectives index](retrospectives/index.md) once pages exist.

**⚠️ Draft pages** require reviewer approval before relying on them for planning. Check for the banner at the top of the page.

---

### Step 4 — Reuse correctly

| Confidence | How to use |
|---|---|
| `high` | Cite directly with the metric |
| `medium` | Cite with attribution ("as documented in…") or verify with the original team before relying on it |
| `low` | Do not rely on for planning decisions |

**Traceability:** every recommendation links back to a `context/` source file via footnotes. If someone asks for the source, follow the footnote to the `context/` path in the [repo](https://github.com/srab2001/lessons-learned-kb).
